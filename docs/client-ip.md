# 访客地址

这一份是给实现者的规格。现在 `REMOTE_ADDR` 是 TCP 对端，`X-Real-Ip` 和 `X-Forwarded-For` 原样放进 `$_SERVER`，程序不根据它们改地址。入口前面会把访客地址写进 `X-Real-Ip`，但只有对端是入口时才能信。

## 配置

| 变量 | 默认 | 作用 |
|---|---|---|
| `TRUSTED_PROXIES` | 空 | 逗号或空白分开的 CIDR。空表示不信任任何代理，`REMOTE_ADDR` 保持 TCP 对端。 |
| `REAL_IP_HEADER` | `X-Real-Ip` | 从哪个请求头读访客地址。只允许 `X-Real-Ip` 和 `CF-Connecting-IP`。别的值拒绝启动。 |

BaseHub 里这是进程环境。没设 `TRUSTED_PROXIES` 的进程跟现在一样。

对端落在 `TRUSTED_PROXIES` 里，并且头的值是单独一个 IP 时，用这个 IP 作为 `REMOTE_ADDR`。头不合法、为空、带逗号、带端口，就保持 TCP 对端，请求继续。不信任的对端也保持 TCP 对端，并且不要把那个头的值抄进 `REMOTE_ADDR`。

`$_SERVER` 里原来的头仍在，方便应用自己核对。访问控制不在这里做。入口的白名单看的是连到入口的地址，PHP 改 `REMOTE_ADDR` 不能放行或拒绝连接。

## 性能

网段在启动时编成表。热路径上每个请求只做一次网段匹配和一次 IP 解析。不查 DNS，不读环境变量。

`TRUSTED_PROXIES` 为空时，连匹配都跳过，直接用已经拿到的对端地址。这是默认，不能比现在慢。

不信任时不要为了丢弃头去复制整份请求头。只是不采用那个值。

## 稳定性

环境变量在进程启动时读一次。改环境要换容器，不在请求中途重新解释网段。一个写错的 CIDR 让进程拒绝启动，并写明哪一段不合法，而不是带着半份名单继续跑。

非法的头值不算错误日志的每一条请求都打。同一个进程里对这种头只在第一次见到时打一行，避免坏客户端把错误日志打满。`REMOTE_ADDR` 仍是对端。

只影响这一次请求的 `$_SERVER`。worker 模式上下一个请求重新填，不能把上一个访客留在进程里。

线程超时或打满 `MAX_REQUESTS` 回收时，地址表留在进程里，不要每条线程各解析一次环境变量。

## 先不做

- 从 `X-Forwarded-For` 里挑一跳。那个头可以有许多地址，这里不解析它。
- 用 `REMOTE_ADDR` 做平台白名单。
- 信任任意头部名字。只允许表里的两个。
